# دليل عملي — المرحلة الثانية من الفوترة الإلكترونية (الربط والتكامل)

> دليل مختصر بالعربية لاستخدام هذه المكتبة في المرحلة الثانية من منظومة «فاتورة» لدى هيئة الزكاة والضريبة والجمارك. يفترض معرفة أساسية بـ PHP وComposer. **ابدأ دائماً على بيئة المحاكاة قبل الإنتاج.**

## الصورة الكاملة في خمس خطوات

| # | الخطوة | ما يحدث | من المكتبة |
|---|---|---|---|
| ١ | تجهيز وحدة الفوترة (EGS) | تعريف بيانات المنشأة والفرع والجهاز | مصفوفة `egs_unit` |
| ٢ | المفاتيح وطلب الشهادة | توليد زوج مفاتيح secp256k1 وCSR | `generateNewKeysAndCSR()` |
| ٣ | شهادة الالتزام ثم الإنتاج | OTP من بوابة فاتورة ← CSID التزام ← اجتياز فحوصات الالتزام ← CSID إنتاج | دوال إصدار الشهادات في `EGS` |
| ٤ | إنشاء الفاتورة وتوقيعها | فاتورة مبسطة UBL + الختم التشفيري | `sign()` |
| ٥ | الإبلاغ | إرسال الفاتورة الموقعة إلى واجهات فاتورة | `report()` |

## ١ · تجهيز وحدة الفوترة

```php
$egs_unit = [
    'uuid'        => '6f4d20e0-6bfe-4a80-9389-7dabe6620f12',
    'custom_id'   => 'EGS1-886431145',
    'model'       => 'IOS',
    'CRN_number'  => 'رقم السجل التجاري',
    'VAT_name'    => 'اسم المنشأة الضريبي',
    'VAT_number'  => '3xxxxxxxxxxxxx3',
    'location'    => [ 'city' => 'الخبر', 'street' => '...', 'building' => '...', 'postal_zone' => '...' ],
    'branch_name'     => 'اسم الفرع',
    'branch_industry' => 'نشاط الفرع',
];
// البيئة: EGS::ENV_SANDBOX (بوابة المطورين) أو EGS::ENV_SIMULATION أو EGS::ENV_PRODUCTION
$egs = new \ZATCA\EGS($egs_unit, \ZATCA\EGS::ENV_SANDBOX);
```

> اختيار البيئة يضبط عنوان بوابة فاتورة **و** قالب توقيع الشيفرة داخل الـ CSR معاً
> (`TSTZATCA-Code-Signing` / `PREZATCA-Code-Signing` / `ZATCA-Code-Signing`).

## ٢ · المفاتيح وطلب الشهادة

```php
[$private_key, $csr] = $egs->generateNewKeysAndCSR('اسم الحل التقني');
```

- يتطلب امتداد `ext-openssl` فقط — لا حاجة لأمر `openssl` في النظام ولا لاستدعاء `shell_exec`.
- المفتاح الخاص يُولَّد في الذاكرة ولا يُكتب على القرص إطلاقاً.
- **خزّن المفتاح الخاص في مكان آمن** (خزنة أسرار/متغيرات بيئة) — لا تضعه في المستودع أبداً.

## ٣ · شهادتا الالتزام والإنتاج

1. من بوابة **فاتورة** أنشئ وحدة جديدة واحصل على **OTP** (صلاحيته دقائق).
2. اطلب شهادة الالتزام بالمفتاح والـ CSR والـ OTP.
3. شغّل فحوصات الالتزام على فواتير تجريبية حتى تجتاز المتطلبات.
4. اطلب شهادة الإنتاج (CSID النهائي) — وبها تُبلغ الفواتير الحقيقية.

## ٤ · إنشاء الفاتورة وتوقيعها

```php
$invoice = [ /* البنود والإجماليات والضريبة — انظر phase-2.php لمثال كامل ببنود وخصومات */ ];

[$signed_xml, $invoice_hash, $qr, $invoice_uuid] =
    $egs->signInvoice($invoice, $egs_unit, $certificate, $private_key);
```

الناتج: XML موقّع بالختم التشفيري + الهاش + محتوى QR للمرحلة الثانية (يتضمن التوقيع)
+ **معرّف UUID خاص بكل فاتورة** يجب إرساله مع الفاتورة إلى الهيئة.

## ٥ · الإبلاغ

```php
// فحص الالتزام قبل الإنتاج
echo $egs->checkInvoiceCompliance($signed_xml, $invoice_hash, $certificate, $secret, $invoice_uuid);

// بعد اجتياز الفحوصات: شهادة الإنتاج ثم الإبلاغ
[$request_id, $production_certificate, $production_secret] =
    $egs->issueProductionCertificate($request_id, $certificate, $secret);

echo $egs->reportInvoice($signed_xml, $invoice_hash, $production_certificate, $production_secret, $invoice_uuid);
```

- الفواتير **المبسطة** تُبلَّغ خلال أربع وعشرين ساعة (Reporting).
- الفواتير **الضريبية القياسية B2B** تخضع للاعتماد اللحظي (Clearance) — راجع حدود دعم المكتبة قبل الاعتماد عليها في B2B.

## أخطاء شائعة

- **OTP منتهي**: أعد توليده من البوابة قبل الطلب مباشرة.
- **رفض CSR**: تحقق من صيغة رقم ضريبة القيمة المضافة (خمس عشرة خانة، يبدأ وينتهي بثلاثة) ومطابقة بيانات الوحدة.
- **فشل التوقيع**: تأكد أن المفتاح الخاص هو نفسه المستخدم في إصدار الشهادة.
- **اختلاف بيئة**: شهادات المحاكاة لا تعمل على الإنتاج والعكس صحيح — تأكد من تمرير البيئة الصحيحة عند إنشاء `EGS`.
- **اسم بائع طويل**: حقل الطول في TLV بايت واحد، فلا يتجاوز أي حقل ٢٥٥ بايت (الحرف العربي بايتان).

## إخلاء مسؤولية

هذا الدليل والمكتبة عمل مجتمعي وليسا منتجاً للهيئة. المرجع النهائي هو وثائق الهيئة الرسمية وفحوصات الالتزام لبيئتك أنت.
